### CERT2-01 — Unjustified SCOPE_OVERRIDE: MP-72-013 and MP-72-014

**Severity:** CRITICAL (certification-blocking)

**Requirement (canonical, `docs/MASTER_PRODUCTION_CHECKLIST.md` §72):**
- MP-72-013 — "Blurry assets."
- MP-72-014 — "Wrong resolution."

**Claim falsified.** `scripts/generate_resolution_queue.py` forces both to `EXTERNAL_BLOCKER`:

> "The irreducible remainder is a physical PANEL … a second density bucket … are all
> properties of real hardware, not of a framebuffer."

and the audit rows state *"Only one density bucket exists on this device, and blurriness is by
definition a wrong-bucket symptom"* → *"nothing further is closable in-repo."*

**Exact reproduction.**

```bash
grep -rn "Image\.asset\|AssetImage\|DecorationImage\|ExactAssetImage" lib/
awk '/^flutter:/{f=1} f{print}' pubspec.yaml | sed -n '1,15p'
python3 - <<'PY'
import struct
from pathlib import Path
def dim(p):
    d=open(p,'rb').read(24); return struct.unpack('>II',d[16:24])
for p in sorted(Path("android/app/src/main/res").rglob("*.png")):
    print(f"{p.parent.name:24s} {p.name:26s} {dim(p)}")
PY
```

**Observed.**

- The Flutter asset bundle declares **no images at all**. `pubspec.yaml` `assets:` is exactly
  `tr-TR.json`, `ringtone.wav`, `siren.wav`, `THIRD_PARTY_NOTICES.txt`.
- The only raster draw in `lib/` is `Image.file` (`fake_call_screen.dart:358`) — a user-picked
  photo at runtime, not a shipped asset.
- Every shipped raster lives in `android/app/src/main/res` and **all five density buckets are
  present at mathematically exact resolutions**:
  - `mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher.png` = 48 / 72 / 96 / 144 / 192
  - `drawable-{m,h,xh,xxh,xxxh}dpi/splash.png` and `android12splash.png` = 288 / 432 / 576 / 864 / 1152 (+ full `-night-` set)
  - Generated by `flutter_launcher_icons` / `flutter_native_splash` from a **2048×2048** source,
    so upscaling — the only mechanism that produces a blurry or wrong-resolution asset — is
    arithmetically impossible.
- The repository **already ships a reproducible in-repo measurement of this exact surface**:
  `docs/audit/evidence/assets.json`, emitted by `scripts/audit_evidence/assets.py`, enumerating
  all 11 launcher resources plus `"customIconFonts": 0`, `"dynamicIconLookupSites": []`, and
  *"every glyph is a const IconData from the Material font, resolved at compile time."*

**Expected.** Both rows are answerable here, deterministically, with no hardware. `assets.json`
carries `launcherIcons` as a **CENSUS** property — it lists the 11 files but applies **no rule
comparing pixel dimensions to the density bucket**. That missing rule is the whole remaining work,
it is ~15 lines, and it is in-repo.

The override's stated blocker is inverted: the *device* has one bucket, but the *repository* has
all five, and their correctness is arithmetic, not a panel observation.

**Why the existing gate missed it.** `scripts/verify_resolution_classification.py` does not
reimplement the classifier — by design it imports it:

> "The classification itself is deliberately NOT reimplemented here. It is imported from
> `generate_resolution_queue.py`."

So `SCOPE_OVERRIDES` is applied *before* the gate counts, and the gate then verifies
`IN_REPO_RESOLVABLE == 0` against the very classification the override produced. **A manual
override is self-certifying; no gate in the 18 can contradict it.**

**Resolvable:** IN-REPO, now.

**Remediation direction.** Add a dimension rule to `scripts/audit_evidence/assets.py` asserting
each bucket's pixel size against its density multiplier (mdpi×1, hdpi×1.5, xhdpi×2, xxhdpi×3,
xxxhdpi×4) with a negative control; regrade MP-72-013/014 to PASS on that measurement; delete both
overrides.

### CERT2-03 — Offline banner clips its own label at supported text scale (runtime-verified)

**Severity:** HIGH (certification-blocking: runtime-verifiable, P3-class §72 defect, in the one
production change in this batch)

**Requirement.** MP-05-018 "Dynamic Type/font scaling düşünülmüş." is graded **PASS** with evidence
*"`lib/main.dart` MediaQuery textScaler override preserves Android font scaling to 2.0x."* The app
therefore commits to rendering correctly up to 2.0×.

**Claim falsified.** `lib/widgets/connectivity_banner.dart` (added by `d223d95`, the banner fix
under certification) states:

> "Explicit height so the shell's reservation and the banner's own geometry cannot drift apart. It
> equals what the row already measured intrinsically (the dense leading glyph is the tallest
> child), so **this pins the current appearance rather than changing it**."

"The dense leading glyph is the tallest child" is true **only at textScale 1.0**. `contentHeight =
IconSizes.dense = 16`; the label is `fontSize: 13`, which at 1.5× is ≈19.5 dp — taller than the
fixed box. The `SizedBox` stops being a record and becomes a clip.

**Exact reproduction.**

```bash
flutter build apk --debug --flavor play
adb install -r build/app/outputs/flutter-apk/app-play-debug.apk
adb shell cmd connectivity airplane-mode enable
adb shell settings put system font_scale 1.5
adb shell am start -n com.poyrazoncel.korubeni/.MainActivity
# unlock PIN 2468, then:
adb shell screencap -p /sdcard/x.png && adb pull /sdcard/x.png
```

**Observed.** API 36 emulator, 1080×2400 @ 420 dpi, airplane mode on, freshly built HEAD APK:

- **fontScale 1.0** — "Çevrimdışı Mod" renders in full; cedilla on `Ç` and dots on `ı` intact.
- **fontScale 1.5** — the label is cut off at roughly 40% of glyph height. Descenders and the lower
  baseline are sliced by the banner's bottom edge; `Çevrimdışı` reads as `Cevrimdisi`.

Page content beneath is **not** overlapped at either scale — the reservation itself is correct. The
clipped element is the banner's own content row.

**Expected.** The banner's label must render fully anywhere within the declared 2.0× ceiling, and
`reservedHeight` must follow the scaled content.

**Why the existing gate missed it.**
- `docs/audit/evidence/text_scale.json` covers exactly five surfaces — `consent-row`,
  `legal-version-line`, `readiness-chip-strip`, `settings-row`, `two-button-action-bar`.
  `ConnectivityBanner` is not among them.
- `test/screens/connectivity_banner_reserves_space_test.dart` has two tests: a constants identity
  (`reservedHeight == verticalPadding*2 + contentHeight`) and a single-inset padding check at
  **implicit textScale 1.0**. It never scales text, and it never renders `main_navigation`, so it
  also does not assert that the shell applies the reservation at all.
- `grep -rn "ConnectivityBanner" test/ | grep -i scale` → no matches.

**Resolvable:** IN-REPO and RUNTIME-VERIFIABLE NOW.

**Remediation direction.** Derive the content height from
`MediaQuery.textScalerOf(context).scale(13)` (max against `IconSizes.dense`) so `reservedHeight`
tracks it, or drop the `SizedBox` and measure the row intrinsically; add the banner to the
`text_scale.json` surface list at 1.0 / 1.3 / 2.0.

### CERT2-06 — `kNoSpinnerJustified` PIN-gate reason is factually wrong (behaviour is fine)

**Severity:** LOW

**Claim falsified.** `test/screens/button_loading_state_test.dart` justifies
`safety_session_pin_gate.dart::_verificationInProgress` as *"Local keystore comparison, **not I/O
with observable latency**."*

**Observed.** `_submit()` awaits `PinVerificationService.verify()`, which performs
`_storage.read(key: SecureStorageKeys.userPin).timeout(_operationTimeout)` — a `flutter_secure_storage`
platform-channel read against Android Keystore, at up to three call sites, and it then awaits
`PinLockoutService.reset()` / `registerFailure()`, which are two further secure-storage reads plus a
write. The explicit `.timeout(_operationTimeout)` is the code conceding the latency the reason
denies.

The second half of the reason ("a spinner would leak timing") is also weak: the dialog already
nulls both buttons and sets `enabled: !_verificationInProgress` on the field, so the same timing is
already observable.

**Not a missing-feedback defect.** The control genuinely disables (field + both actions), which the
verifier asserts for exempted flags too. The UX state is legitimate; only the recorded reason is
untrue, and the map's own contract is *"Each entry is a REASON, not a suppression: if the reason
stops being true the entry has to change."*

**Resolvable:** IN-REPO (rewrite the reason to the true one: a toggle-free modal whose loading
affordance is its disabled field and actions).
